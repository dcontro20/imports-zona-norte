## 3 · Backup automático a Google Drive (5df137f + 4f02ab2)

### El problema

Los backups a Drive estaban subiendo **hasta el 21/04** porque un agente Claude
(yo en sesiones anteriores) los subía manualmente vía MCP de Google Drive. Esas
sesiones viven poco y el cron que disparaba el agente se expiró. El 22/04 no
subió nada.

Último backup automático en Drive: `IZN_Backup_2026-04-21_03-03.json`.

### Intento 1 — Service Account (fracasó)

Configuramos una Service Account con key JSON, compartimos la carpeta de Drive.
Pero Google NO le da storage propio a los SA en My Drive personal — solo en
Shared Drives (requiere Google Workspace). Error explícito:
> `Service Accounts do not have storage quota. Leverage shared drives...`

### Intento 2 — OAuth 2.0 con cuenta personal (funcionó)

Pivoteamos a OAuth. Proceso completo:

1. **Google Cloud Console**: crear OAuth Client ID tipo "Desktop app".
   Consent Screen publicada (Published) para que refresh tokens no caduquen a 7 días.
2. **scripts/auth-oauth.mjs**: levanta server HTTP local en puerto random (4000-4999)
   como redirect_uri. Abre browser con URL de consent. Captura el code del callback.
   Intercambia code por refresh_token. Guarda en `.credentials/drive-oauth-token.json`.
3. **scripts/backup.mjs**: modificado para usar `google.auth.OAuth2` con refresh_token.
   Hook `oauth2.on("tokens", ...)` persiste access_tokens refrescados automáticamente.

### LaunchAgent macOS

`scripts/com.izn.backup.plist` instalado en `~/Library/LaunchAgents/`.

Primer intento usaba `bash -c "cd ... && node ..."` → falló con `EPERM uv_cwd`
(macOS bloquea acceso a Desktop desde bash bajo launchd).

Segundo intento: node directo + `<WorkingDirectory>` en el plist → funcionó.

Schedule: `StartCalendarInterval` Hour 3, Minute 3 (3:03 AM ART diario).

### Nombres de archivo amigables

- **Local** (sort-friendly): `IZN_Backup_2026-04-22_07h30.json`
- **Drive** (human-friendly): `IZN · Backup del Martes 22 Abr 2026 · 07h30 · 312 registros.json`

Helpers `localFileName(date)` y `driveFileName(date, records)` en backup.mjs.

### Debug notable

Bajo launchd el proceso se quedó hung con STAT=U (uninterruptible wait) la primera
vez. Proceso manual funcionaba en 7 segundos. La causa parecía ser un proceso
viejo bloqueado — matando con `kill -9` y reintentando, todo empezó a andar.
Después de eso, runs consistentemente en ~20s.

Dos runs de verificación sin --quiet confirmaron el flow completo; después puse
--quiet y los runs diarios son silenciosos (stdout vacío es success).
